# Аудит реализации и статус готовности

Дата: 2026-09-09. Область аудита — только вариант 1 задания: измерение
габаритов товара на конвейере.

## Вывод

Проект содержит работающий офлайн-прототип геометрического ядра и расширенный
контракт для профилометрического контура. Готовность физического измерительного
поста и выполнение точности задания пока **не доказаны**: нет данных с сенсора,
калибровки рамы и приёмочной серии.

## Что изменено по результатам аудита

| Риск из аудита | Реализованное доказательство | Оставшаяся граница |
|---|---|---|
| Товар касается ленты, а высотный фильтр стирает основание | `ObjectObservation` принимает уже выделенный foreground, включая Z=0; копланарный input получает доменную причину вместо Qhull. | Физическая foreground-маска и модель фона требуют записей стенда. |
| Неполный ракурс выдаёт неполный box | `CaptureEvidence` проверяет обязательные сенсоры, пропуски и границу ROI; результат `rejected` содержит причину. | Набор обязательных ракурсов и ROI нужно калибровать на установке. |
| Два товара объединяются, выброс меняет размер | DBSCAN оставляет одну поддержанную компоненту, шум отбрасывает, несколько объектов отклоняет. | Параметры кластеризации требуют подбора по реальным профилям. |
| Преобразование и сообщения допускают NaN/Inf или изменение после проверки | Конечность, жёсткость и неизменяемые копии проверяются в `Calibration`, transforms и profile/message contracts. | Метрическая ошибка внешней калибровки не измерена. |
| `INSERT OR IGNORE` скрывает иные проблемы | Outbox возвращает `False` только после проверки повторного `measurement_id`; остальные integrity errors не подавляются. | Нет согласованного реального WMS transport. |
| Последовательные сечения сдвигаются вместе с лентой | `LaserProfile` хранит отсчёт энкодера; registration компенсирует X до общей позиции. | Шаг колеса, проскальзывание и временная синхронизация не измерены. |
| Open3D представлен как exact MVBB | Алгоритм именуется `open3d-face-aligned-approx`; exact MVBB остаётся открытым требованием. | Нужен независимый верифицированный решатель и сравнение. |

## Выполнение требований

| Требование | Статус | Доказательство / ограничение |
|---|---|---|
| R01: три габарита на движущейся ленте | Частично | Есть contracts, encoder registration и интеграционный тест; live SDK и стенд отсутствуют. |
| R02: minimum-volume box | Открыто | Есть только приближённый OBB baseline. |
| R03–R04: диапазон и 1 м/с | Открыто | Есть расчёт покрытия и синтетические границы; нет физической проверки. |
| R05: интервал 3 с | Частично | Он учтён в плане испытаний; state machine проходов не реализована. |
| R06: ±max(5 %, 5 мм) | Открыто | Формула и валидация есть, измеренной ошибки нет. |
| R07: WMS | Частично | Durable outbox и dispatcher есть; endpoint/auth/SLA отсутствуют. |
| R08: сенсоры, монтаж, вычислитель | Проектно готово | Конкретный BOM, координаты и расчёты — в `docs/hardware.md`. |
| R09: алгоритмы и метрики | Частично | Архитектура и метрики описаны, нет измеренного отчёта. |
| R10: PDF | Готово после генерации | PDF включает аудит, оборудование, расчёты, алгоритм, ограничения и источники. |

## Что проверяет программный набор

Запускаются pytest, Ruff, Ruff format, mypy и проверка `uv.lock`; workflow
`.github/workflows/quality.yml` выполняет эти проверки на push и pull request.
Тесты охватывают нормальные и невалидные входы, edge cases и сквозную цепочку
`ProfileBundle → registration → segmentation → ObjectObservation → result`.
Синтетические тесты не являются измерением точности камеры, профиломера,
калибровки, материала товара или задержки WMS.

## Условия перед production-утверждением

1. Провести one-head и three-head gates из `docs/hardware.md`.
2. Выполнить независимую метрологическую калибровку и сохранить остатки.
3. Собрать 5400 предъявлений по плану, включив отказы и пропуски в знаменатель.
4. Выбрать и независимо проверить exact MVBB backend, если R02 остаётся буквальным.
5. Согласовать WMS endpoint, авторизацию, идемпотентность и допустимую задержку.
