# Требования и трассируемость

Этот документ фиксирует требования варианта 1 тестового задания. Он является источником acceptance criteria для реализации и экспериментов.

| ID | Требование | Доказательство выполнения |
|---|---|---|
| R01 | Измерять три габарита товара на движущемся конвейере. | Сквозной тест `frame bundle → MeasurementResult`; отдельные метрики L/W/H. |
| R02 | Использовать минимальный по объёму прямоугольный параллелепипед. | Инвариантные и аналитические тесты MVBB; сравнение с независимым backend. |
| R03 | Покрыть товары 10×10×10…400×300×300 мм. | Датасет и hardware tests на границах диапазона. |
| R04 | Работать при ширине ленты 600 мм и скорости 1 м/с. | Расчёт FOV; запись или стенд при измеренной скорости. |
| R05 | Учитывать интервал 3 с между товарами. | Event state machine и тесты двойных/пропущенных событий. |
| R06 | Соблюдать ±max(5%, 5 мм) для каждого размера. | Сравнение с независимым ground truth; all-dimensions pass rate. |
| R07 | Передавать размеры в WMS. | Интеграционные тесты HTTP-клиента, durable outbox и retry. |
| R08 | Обосновать сенсоры, размещение и вычислитель. | `docs/hardware.md`, FOV-расчёт и ссылки на datasheet. |
| R09 | Обосновать алгоритмы, библиотеки и метрики. | Architecture decision records и benchmark report. |
| R10 | Подготовить PDF-отчёт. | Финальный PDF с источниками, результатами и ограничениями. |

## Правило точности

Для эталонного измерения \(d_i\) определяется допуск:

\[
T_i = \max(0.05d_i, 5\text{ мм}).
\]

Товар проходит проверку только при:

\[
|\hat d_i-d_i| \leq T_i
\]

для всех трёх измерений. Эталон \(d_i\) берётся из независимого измерительного контура. Отказ, пропуск товара и дублированное событие не считаются успешным измерением.

## Неподтверждённые свойства

До получения экспериментальных данных нельзя утверждать, что выбранный сенсор обеспечивает точность R06, что система измеряет прозрачные и блестящие товары или что целевая latency достижима при 1 м/с.
## Контролируемые программные инварианты

`MeasurementResult.within_operating_range` показывает, помещается ли отсортированный
набор габаритов в диапазон задания: 10–400 мм по максимальной стороне и 10–300 мм
по двум другим. Значение `false` не является доказательством ошибки CV: это
сигнал, что результат не относится к целевому operating range и не должен
автоматически приниматься downstream-системой.
